# ArcDesk — instructions for Claude

A virtual desktop for GNOME Shell: a free grid of slots on the wallpaper, holding app icons,
virtual folders and folder shortcuts. It is **not** a view of `~/Desktop` — nothing here touches
the filesystem. The arrangement lives in GSettings, and ArcDock appends to it.

There is **one independent grid per monitor**. Every screen gets its own slots, an item remembers
which monitor it lives on, and an icon can be dragged from one screen to another. See
**One grid per monitor** below — it is the single most load-bearing section of this file.

## How to reload after editing JS

- **This machine runs Wayland.** `gnome-extensions disable ArcDesk@claudson; gnome-extensions enable
  ArcDesk@claudson` usually does **not** pick up an ESM edit: the Shell cannot re-import a module it
  has already loaded, so `enable()` runs again over the *old* code. The symptom is a change that
  "did nothing" — and worse, a fix that looks like it failed when it didn't. If a new log line does
  not appear after the enable, you are running stale code. **Log out and log back in.** That is the
  reliable path here, and the only one.
- `Alt+F2` → `r` → `Enter` restarts the shell and forces a reimport, but that is **Xorg only**;
  under Wayland the Looking Glass `r` command is not available.
- CSS-only changes reload along with the shell, so a stylesheet tweak is cheap. Note that
  `stylesheet.css` is **generated** — it is `common.css ++ local.css` from
  `~/.local/share/arcsuite/`, regenerated by `sync.sh`. Edit `local.css`, never `stylesheet.css`.
- The journal is the only real feedback loop:
  `journalctl --user -f -o cat _COMM=gnome-shell | grep -i arcdesk`.

## Architecture

```
extension.js              — entry point: ArcDeskExtension.enable/disable. Reads keys, owns ONE DeskManager.
prefs.js                  — Adw preferences: Appearance / Behavior / Items (reuses src/deskLayout.js).
src/
├── config.js             — SIZE, ANIM, TIMING, MERGE, ItemType, DeskTheme, LabelPosition, GridOrigin, State.
├── trackers.js           — SignalTracker, TimeoutTracker (verbatim from ArcDock).
├── cursor.js             — cursor helpers (setPointer/setDefault).
├── glassEffect.js        — applyGlass(): the blurred panel background.
├── deskLayout.js         — the model: desk-items / desk-placements / desk-folders. GLib + Gio only.
├── appList.js            — getInstalledApps() / lookupApp(): Shell.App resolution for the model.
├── arcdockBridge.js      — reports ArcDesk app activations to ArcDock's public usage API.
├── deskManager.js        — DeskManager: the single DeskLayout, one DeskSurface per monitor, the
│                           single FolderPopup, the FullscreenWatcher and the grab arbitration.
├── deskSlot.js           — DeskSlot: one fixed cell; paints EMPTY / TARGET / SWAP.
├── deskSurface.js        — DeskSurface: ONE monitor's actor in _backgroundGroup, its metrics, its
│                           slots and its drop delegate. Does not own the model.
├── deskIcon.js           — DeskIcon: one cell's art, label, selection, menu and the four dnd verbs.
├── doubleClick.js        — attachClickOpen(): single vs. double click, with the GNOME 50 fallback.
├── deskIconMenu.js       — DeskIconMenu: the cell's context menu, built on first right-click.
├── folderPreview.js      — createFolderPreview(): the 3x3 folder cover. Pure, no state.
├── folderPopup.js        — FolderPopup: the open-folder panel. Chrome, not desktop layer.
├── ghostFlight.js        — GhostFlight: adopts the dnd drag actor and flies it into its slot.
├── fullscreenWatcher.js  — FullscreenWatcher: primary monitor fullscreen → stop painting. One
│                           instance, owned by the manager.
└── dingWatcher.js        — warnIfDingActive(): the one-time "DING is also drawing here" notice.
```

One class = one file = one responsibility. **Anything that needs cleanup never lives loose outside a
tracker.** `src/CONTRACT.md` is the binding interface document — if an implementation has to
diverge, the divergence is written back there *first*.

### Why the surfaces live in `_backgroundGroup`

Each desktop surface is an `St.Widget` added to `Main.layoutManager._backgroundGroup`, sized by
`Layout.MonitorConstraint({index: monitorIndex, workArea: false})`, and raised above the wallpaper
actors with `set_child_above_sibling(surface, null)`. There is one of them per monitor.

The actor covers the whole monitor. The icon grid is positioned inside
`getWorkAreaForMonitor(index)`, converted from stage coordinates to the actor's local coordinates;
this keeps icons clear of panels while allowing diagnostics and background input over the full screen.

`index` and `primary` on a `MonitorConstraint` are **mutually exclusive** — setting one clears the
other — so a per-monitor surface states its index and never its primaryness, even for the surface
that happens to be on the primary screen. Binding to `primary` was the v1 bug: on a two-monitor desk
the whole desktop landed on whichever screen GNOME calls primary, and the other one showed bare
wallpaper.

- **Never a direct child of `global.window_group`.** It looks like the obvious place — the wallpaper
  is in there — but mutter's `sync_actor_stacking()` only lowers *window actors* and *background
  actors* when it restacks. A plain `St.Widget` is neither, so it is left exactly where it was, which
  after the first restack means **on top of every window**. There is no flag to fix that; the fix is
  to be inside a group that mutter treats as background as a whole.
- **Never anchored to `bgManager.backgroundActor`.** That actor is destroyed and rebuilt on every
  wallpaper change, including the automatic ones of a dynamic wallpaper. Anchor to the *group*,
  which survives.
- Hiding in the overview and on the lock screen is **already done for us**:
  `global.window_group.visible` is driven by `Main.sessionMode.hasWindows && !inOverview`, and we are
  inside it. That is why `metadata.json` declares `session-modes: ["user"]` and why `extension.js`
  has no session-mode handler at all — unlike ArcDock, there is nothing to keep alive on the lock
  screen.
- The consequence: the surfaces do **not** appear in the overview, nor in the workspace-switch
  animation. Both render their own separate `Meta.BackgroundGroup`, which never contained our actors.
  That is expected, not a bug — do not "fix" it by cloning ourselves into the overview.
- `hide-in-fullscreen` is a *rendering* switch, not a visibility fix. We already sit under every
  window; the point is that a plain `St.Widget` is not a `MetaCullable`, so it keeps painting under a
  fullscreen game that covers it completely. `FullscreenWatcher` reads
  `global.display.get_monitor_in_fullscreen(index)` — the same value `LayoutManager` uses for
  `trackFullscreen`, already resolved per monitor and already accounting for stacking — rather than
  scanning windows itself. There is **one** watcher, owned by the manager, and it currently reads
  the **primary** index: a game fullscreen on the primary screen quiets the whole set. Making it
  per-screen is one argument (`get_monitor_in_fullscreen(index)` already takes it) plus one watcher
  per surface — do that only if the extra signal connections are worth it, and do not fake it by
  scanning windows.

### One grid per monitor

`DeskManager` owns the whole set: the single `DeskLayout`, one `DeskSurface` per entry in
`Main.layoutManager.monitors`, the single `FolderPopup`, the `FullscreenWatcher` and the grab
arbitration. `extension.js` constructs exactly one manager and knows nothing about surfaces, popups
or monitors — that is why it got *shorter* when ArcDesk gained N screens.

**Monitor identity is the index, because GNOME 50 gives us nothing better.**
`Main.layoutManager.monitors[i]` carries `index`, `x`, `y`, `width`, `height` and `geometry_scale`
— no connector name — and `Meta.Display` exposes no `get_monitor_connector`. So a placement stores
the **monitor index**, and the index is what we live with. Do not go looking for a stable id to
store instead; on this side of the shell there is not one.

**An index that no longer exists degrades, it never destroys.** Indices reshuffle when a screen is
unplugged, so a stored `mon` can point at nothing. The rule is the same one that already governs
`col`/`row` and it is not negotiable: **the stored value is authoritative and is never rewritten
because the current hardware cannot honour it.** An item whose `mon` is out of range is *displayed*
on the primary monitor, in the first free slot there, and its stored record is left exactly as it
was. Plug the screen back in and the arrangement returns intact. A "clean up stale monitor indices"
pass would flatten a two-screen desktop into one screen the first time a laptop is undocked, and
there is no undo for that.

**There is still exactly ONE `DeskLayout` in the process** — now owned by the manager rather than by
a surface, precisely *because* there are several surfaces. A second instance would fight the echo
suppression: each one would snapshot only its own writes and process the other's as external,
rebuilding on the echo of a write it had just made. For the same reason the manager subscribes to
`layout.onExternalChange()` **once** and then calls `refresh()` on every surface. N surfaces each
subscribing would mean N callbacks and N full rebuilds for a single external change, and the surface
that happened to be first would rebuild against a model the others had not seen yet.

**Occupancy is per monitor.** Two items may share the same `{col, row}` as long as their `mon`
differs; clamping, the first-free-slot scan and the collision push all run inside one monitor's grid
before spilling to the primary. `itemAt(col, row, mon)` without the third argument would answer for
the wrong screen.

**Monitor changes rebuild the whole set, not a relayout.** The manager listens to
`Main.layoutManager::monitors-changed` and destroys and rebuilds every surface from the current
`monitors` array. The monitor **count** can change, and a surface is bound to one index for its
lifetime, so `relayout()` cannot express "there is now a third screen". `extension.js` deliberately
does **not** connect that signal any more — two handlers would rebuild twice.

#### Selection uses normal keyboard focus

A surface calls `grab_key_focus()` when clicked so Escape/Enter/Menu work. Selection never calls
`Main.pushModal`: a modal also captures pointer input, so a missed release can make every other
window unclickable. Normal focus transfers automatically when another surface or window is clicked.

#### How a drag crosses between monitors

Nothing coordinates it, and that is the design. The dnd finds its target with
`get_actor_at_pos(Clutter.PickMode.ALL, …)` and walks up from the picked pixel, so a drag that
crosses onto another screen reaches **that** surface's delegate on its own. What each side owes:

- **The accepting surface must not require the source to be one of its own icons.** `_isDropSource()`
  checks that `source.id` resolves in the shared model, nothing more. `_dragIdOf()` falls back to its
  own drag snapshot only when `source === this._drag.icon`; for a foreign source it reads `source.id`
  directly, which is exactly right.
- **The accepting surface writes the move with its own `monitorIndex`.** That single argument is what
  actually moves the item between screens — there is no separate "transfer" path.
- **The origin surface clears its lit slot at its own `drag-end`**, even though its `acceptDrop` never
  ran. dnd emits `drag-end` on the source regardless of who accepted, so `_clearTargetSlot()` there
  covers it. The origin surface must **not** schedule a refresh of its own: the manager refreshes
  everyone, and a surface refreshing itself mid-gesture would destroy the source cell dnd still needs.
- **`onDropOnOther(sourceIcon, dragActor)` is how the accepting surface tells the manager** that
  someone else's item landed here; the manager refreshes all surfaces once. It returning `false`
  means the manager declined and the caller treats the drop as refused.

### Why popups and menus are chrome

`FolderPopup` and `DeskIconMenu` must **not** live on the desktop layer. Everything in
`_backgroundGroup` renders below every window by construction; a folder panel down there would open
*underneath* the browser the user is looking at. So:

- The folder popup adds its root through
  `Main.layoutManager.addChrome(root, {affectsStruts: false, trackFullscreen: true})`.
  `affectsStruts` stays **false**: a monitor-sized strut would zero the work area on every workspace
  the instant the popup is added. It is placed against the *bounds the manager hands it* — the
  monitor of the surface that raised it — so a folder on the right-hand screen opens on the
  right-hand screen.
- The context menu's actor goes into `Main.layoutManager.uiGroup`, which means **this class has to
  destroy it by hand** — nobody else owns it. Null `_menu` *before* calling `destroy()` on it, so the
  close it triggers cannot re-enter, and null the policy *after*, so that close still reaches the
  surface.
- Because the popup is chrome and the surfaces are not, they cannot own each other — and with N
  surfaces there could not be one popup per surface anyway. **`DeskManager` owns the single popup**
  and routes `onOpenFolder(entry, anchorRect)` / `onCloseFolder()` from whichever surface raised it,
  handing that surface's `createFolderIcon` as the popup's `createIcon` and that surface's monitor
  bounds as its `bounds`. That replaces the `setFolderPopup()` / `createFolderIcon()` hooks
  `extension.js` used to improvise. One popup is enough because only one folder is open at a time,
  and it is created on the **first** open, never in the constructor — most sessions never open a
  folder, and a monitor-sized panel idling in `uiGroup` is not free.
- During a drag out of an open popup the surface calls `setDragMode(true)`, which fades the panel and
  then **`hide()`s it**. Fading alone is not enough: `PickMode.ALL` still finds an invisible cell, and
  the drop would land on the panel instead of on the grid. Only an unmapped actor is certainly out of
  the pick. It is faded, **not closed** — closing would destroy the drag's source cell mid-gesture,
  and dnd needs that cell to undo a refused drop.

### The free grid: empty is move, centre is merge, edge is swap

This is the part that differs most from ArcDock's launcher, and the difference is deliberate: a
launcher grid is an *ordered list* rendered in cells, so an insert reflows everything after it. The
desktop is a **free grid** — a position is a fact the user chose, not an index. There is **no
reflow**, ever.

| pointer is over | result |
|---|---|
| an empty slot | **move** — `layout.moveTo(sourceId, col, row, mon)` |
| the middle of an occupied slot, outside the `MERGE.EDGE_RATIO` band on each side | **merge** — create or extend a folder, but only if `canMerge` |
| the edge band of an occupied slot, or the middle of one that cannot merge | **swap** — `layout.swap(sourceId, occupantId)` |
| outside every grid | refused; the art flies home |

`mon` is not a parameter the surface has to work out: it is always **its own** `monitorIndex`. A
move always states a monitor, which is exactly what makes a drop on another screen *be* a move
between screens. `swap` needs no monitor argument because it trades both slots **and** both
monitors — swapping across screens is one call and it does the right thing.

- **Exactly one slot is lit at a time.** At `drag-begin` it is the origin slot, painted `EMPTY` —
  nothing has moved yet, and that is where the icon returns if the gesture ends where it started.
  From the first `handleDragOver` on, it is the slot under the pointer, painted `TARGET` or `SWAP`.
  `SWAP` is painted **differently** from `TARGET` on purpose: two identical highlights would announce
  two free places, and one of them would be a lie.
- **The plate lives on the slot, not on the icon.** The dragged icon hides itself, so a plate hanging
  off it would vanish exactly when it needs to appear — and an empty slot has no icon to hang it off
  at all.
- **`acceptDrop` returns `true` even when nothing changed.** A drop back into the same slot *was*
  handled; returning `false` would make dnd fly the art back to its origin as if the gesture had
  failed, which reads as a bug to the user.
- **`handleDragOver` on an icon returns `CONTINUE`, never `NO_DROP`,** when that icon does not claim
  the drop. The event has to keep bubbling to the surface's delegate, which is what makes the gaps
  between cells and the empty slots work. `NO_DROP` there makes the whole grid inert.
- **The drop delegate lives on the surface actor itself** (`actor._delegate = {…}`). The dnd walks up
  from the picked pixel, so an empty slot or the gap between two reaches it for free.
- **`_setMergeHover(true)` installs a `DND.addDragMonitor`.** That is the *only* way to learn the
  pointer left: `handleDragOver` runs only while we are the target and **there is no
  `handleDragOut`**. Remove the monitor in `destroy()` — leaving it makes the Shell call back into a
  dead actor on the next drag.
- **Every mutation rebuilds through a scheduled idle, never inline.** `acceptDrop` returns into dnd
  code that is still holding the drag actor and the source cell; destroying either of them from
  inside that call is how you get a wedged gesture. A flight in progress *dams* the rebuild, and a
  watchdog opens the dam if a transition never completes.

### The three drag-and-drop laws

Each of these cost a logout to diagnose in ArcDock. They are restated in `src/CONTRACT.md` and they
apply here verbatim.

1. **Nothing of ours may throw inside the dnd's `emit`.** `_Draggable` is a `Signals.EventEmitter`;
   its `emit()` walks handlers in a plain JS loop **with no try/catch**. `drag-begin` comes from
   inside `_gestureRecognized()` and `drag-end` from inside `_dragActorDropped()`. An exception of
   ours rides that emit up and aborts the rest of the gesture — including `_dragComplete()`, which is
   what pops the modal grab pushed at the start of the drag. The symptom is not a lost gesture, it is
   **the whole session's drag-and-drop wedged, until logout.** Every callback handed to the Shell
   goes through `_guard(fn, what)`.
2. **A dragged cell goes out of the pick but is NEVER `hide()`n.**
   `Shell.util_set_hidden_from_pick(actor, true)` plus `opacity = 0`. It has to stay *measurable*: a
   few lines after `drag-begin` the dnd measures `getDragActorSource()` to decide where the airborne
   art is born and where it snaps back to on a refused drop. A hidden actor there is invalid geometry,
   and one NaN spreads — `set_position(NaN)` makes `clutter_actor_allocate` bail on an assertion, the
   actor never gets an allocation, and a flight that was supposed to release the grid may never land.
3. **A full-screen layer must be out of the pick, not merely non-reactive.** The dnd finds its drop
   target with `get_actor_at_pos(Clutter.PickMode.ALL, …)`, and `PickMode.ALL` **sees non-reactive
   actors** — that is exactly what lets an empty slot accept a drop. A screen-sized layer without
   `Shell.util_set_hidden_from_pick` is a **wall**: the pick stops on it, its parent has no
   `_delegate`, and the whole surface goes inert. The wall only goes up on the first flight, which
   gives the bug its "the first reorder works, the second does nothing" face.

### Persistence, and the `desk-items` public contract

Data keys in `org.gnome.shell.extensions.arcdesk`:

| key | type | shape |
|---|---|---|
| `desk-items` | `as` | ordered `["app:firefox.desktop", "folder:<uuid>", "path:/home/u/Downloads"]` |
| `desk-placements` | `s` (JSON) | `{"app:firefox.desktop": {"col": 0, "row": 2, "mon": 1}}` |
| `desk-folders` | `s` (JSON) | `{"<bare-uuid>": {"name": "Games", "apps": ["steam.desktop"]}}` |
| `desk-item-names` | `s` (JSON) | custom display names keyed by the complete app/path item id |

`mon` is the monitor index, and it is **optional on read**: a record without it was written by v1,
which only ever drew on the primary monitor, so that is what its absence *means* — not "unknown".
The first build that resolves such a record rewrites it with an explicit `mon`, so the migration
happens once and silently. A `mon` that is not a non-negative integer is treated as missing, which
is the same path and therefore needs no separate handling.

`desk-items` and `desk-folders` are **unchanged** by the per-monitor work. In particular `desk-items`
is a **public contract**: ArcDock reaches it through
`Extension.lookupByUUID('ArcDesk@claudson').getSettings()` and appends an id when the user picks
"Adicionar à área de trabalho". *Appending is enough* — ArcDesk assigns the first free slot itself,
which is why the schema id, the path and the `type:value` format may not change without updating
ArcDock in the same commit. **ArcDock still knows nothing about monitors**, and it must not have to:
an appended id lands on the **primary** monitor's first free slot. Do not "improve" the contract by
asking ArcDock for a monitor — the whole value of that interface is that it is one array append.

Rules the model enforces, and that nobody else may reimplement:

- **`parseDeskId` splits on the FIRST `:` only.** The value is a path or an app id and may well
  contain more colons.
- **An id whose type this version cannot render is skipped for display and preserved verbatim on
  write.** Anything else makes an older ArcDesk silently delete a newer one's items — the failure
  mode of every "clean up unknown entries" loop ever written.
- **An `app:` whose `.desktop` is not installed keeps its slot and its placement**, it is just not
  drawn. A package upgrade removes and re-adds the file within a few seconds; that must not destroy
  the arrangement.
- **A folder with fewer than two resolvable members is not a folder.** One member dissolves back into
  that app **in the folder's own slot**; zero members disappears. Checked on *every* build, not only
  on drag-out, because uninstalling also shrinks a folder.
- **An id with no placement gets the first free slot on the primary monitor**, scanned column-major
  from the origin (`col` 0, rows 0..n, then `col` 1, …). This is precisely what makes ArcDock's "just
  append the id" contract work. `firstFreeSlot(grids, mon)` only spills onto another monitor when the
  requested one is genuinely full.
- **Positions are authoritative and are never rewritten when the hardware shrinks.** An item outside
  the current `cols`×`rows` is clamped **for display only**, and an item whose `mon` is out of range
  is drawn on the primary **for display only**. Both leave the stored record untouched. Unplugging a
  monitor must not flatten a carefully arranged desktop into the top-left corner of one screen.
- **Write only on real change.** `build()` runs often, and an unconditional write is dirty dconf for
  free. Compare the *serialised* form, with folder keys sorted so the comparison is a plain string
  compare.
- **Echo suppression is mandatory.** `DeskLayout` is the only writer inside the shell process, but
  ArcDock writes `desk-items` and `prefs.js` writes from another process entirely, so we must listen.
  Snapshot every value we write, swallow exactly **one** identical notification, then zero the
  snapshot — so a later external change, even back to the same value, is processed normally.
  `onExternalChange()` exists instead of a raw `changed::` connect precisely so that nobody can
  bypass this. **There is exactly one `DeskLayout` in the process**, owned by `DeskManager`; a second
  instance would fight the suppression, and with one surface per monitor a per-surface model would
  guarantee several.
- **The manager subscribes once; the surfaces never do.** N surfaces on one model would mean N
  callbacks and N full rebuilds per external change. The manager takes the single subscription and
  fans out `refresh()`.
- Consequently, `extension.js` connects `changed::` to the eight *appearance* keys and to **none** of
  the three data keys. Adding one there would give a second, unsuppressed listener that rebuilds on
  the echo of its own write, mid-drag.

### Double click on GNOME 50

`Clutter.ClickAction`, `Clutter.TapAction` and `Clutter.Event.get_click_count()` were **removed** in
GNOME 49/50. `get_click_count()` in particular does not merely return a wrong number — it does not
exist in Clutter-18 and throws. The replacement is `Clutter.ClickGesture` /
`Clutter.LongPressGesture`, and all of that lives in `src/doubleClick.js` so exactly one file has to
be revisited when the next version moves the ground again.

- Primary path: one `Clutter.ClickGesture({required_button: Clutter.BUTTON_PRIMARY})`, branching on
  `gesture.get_n_presses()` — `>= 2` is a double click, `1` is a single. No timer, immediate
  selection on the first click, and the user's `double-click-time` / `double-click-distance` are
  respected for free.
- **The safety net is not optional.** `get_n_presses()` exists on `Clutter.PressGesture` in Clutter-18
  *by introspection*, but it was never verified in a live compositor. So probe once at attach time
  (`typeof gesture.get_n_presses === 'function'`) and fall back to manual timing against
  `Clutter.Settings.get_default().double_click_time` — defaulting to `TIMING.DOUBLE_CLICK_FALLBACK_MS`
  if even that read throws. Which path was taken is logged once at `console.warn`, so the journal
  answers the question on the very first run rather than after a bug report.
- `DeskIcon` extends **`St.Widget`, not `St.Button`**, for the same reason: `St.Button`'s `clicked`
  fires on the *first* press of a double click, so an "open on double click" built on it opens on the
  single click too.
- **`_swallowClick()` guards with a monotonic window, not a flag.** From GNOME 49 on, the click is
  recognised by a gesture running *outside* dnd's event propagation, and it can arrive **after**
  `drag-end`, with `_dragging` already false. So compare
  `GLib.get_monotonic_time() - this._dragEndedAt` against `TIMING.DRAG_CLICK_GUARD_US`. A monotonic
  clock dies with the object; a timeout would be one more resource to cancel and one more way to
  leak.

### Reporting app clicks to ArcDock

`arcdockBridge.js` notifies `ArcDock@claudson.recordExternalAppClick()` when `_activate()` is about
to activate an app. It passes primitive values and `source = 'arcdesk'`; ArcDock remains the only
SQLite writer. Presence means `ExtensionState.ACTIVE`, and neither the extension manager state nor
the foreign extension object is cached — both can become stale across extension rebases. Selection
alone is not usage: a double-click activation, Enter, or the menu's “Abrir” counts exactly once.

### The dock does not reserve a full-width strip

ArcDock is an overlay centered on only part of one monitor. ArcDesk therefore does not subtract
`SIZE.DOCK_RESERVE` from every row calculation: doing so wastes the entire bottom strip on every
monitor. Users may place an icon behind the dock deliberately; the right and bottom edge slots are
created whenever the visible icon art fits, even if the cell's invisible padding extends farther.

### Filesystem I/O

**Never synchronous inside the shell.** A sync `query_info()` on a dead NFS mount freezes the whole
session. `*_async` with one `Gio.Cancellable` per job, cancelled in `destroy()`, and every callback
re-checks validity before touching an actor.

`prefs.js` is a different process and a plain GTK app, so the sync `query_info()` it uses for a
folder's icon is fine there — a stalled preferences window is not a stalled compositor.

### Import rules

- External imports (`gi://`, `resource:///`) first, blank line, then relative ones.
- Relative paths always carry the explicit `.js` extension (ESM in GJS requires it).
- `extension.js` and `prefs.js` are the only files whose paths GNOME fixes; everything else lives
  under `src/`.
- **`src/deskLayout.js` may import only `GLib` and `Gio`.** `prefs.js` runs in a separate process with
  no `St`, no `Shell` and no `Main`, and it reuses that file to render the Items page. This is why
  `DeskLayout.build()` takes `Shell.App[]` as an *argument* instead of resolving apps itself. If you
  find yourself wanting `St` in `prefs.js`, you have taken a wrong turn — the Items page lists raw
  ids from `layout.order` + `parseDeskId` and renders them with `Gio.DesktopAppInfo.new(appId)`.
- `extension.js` imports **only** `config.js`, `deskManager.js` and `dingWatcher.js`. It no longer
  imports `DeskSurface`, `DeskIcon` or `FolderPopup`: if it needs one of those again, something that
  belongs in the manager has leaked upwards.

## Code conventions

### Naming and visibility
- Public surface: no prefix (`destroy`, `refresh`, `metrics`). Private: `_` prefix.
- Top-level constants in UPPER_SNAKE grouped in `Object.freeze({...})` objects per category.
- Magic strings for state **never loose** — always a frozen enum (`State.DRAGGING`,
  `SlotPaint.TARGET`), compared against the constant.
- Comments in **pt-BR**, user-facing strings in **pt-BR**, gschema and prefs UI strings in
  **English**. This matches ArcDock exactly and is not up for renegotiation per-file.
- 4-space indent, single quotes, semicolons.

### Lifecycle
- Every class that connects a signal, registers a timeout or allocates an actor **must have
  `destroy()`** undoing everything it created, and `destroy()` is idempotent.
- Prefer `SignalTracker` / `TimeoutTracker` over loose `_xxxId` fields.
- `DeskIcon._onDestroyed()` is wired to **both** the `'destroy'` signal and the JS `destroy()`
  override: when the surface takes down a whole row, Clutter destroys the cells internally and only
  the signal reaches both paths.
- Selection takes normal keyboard focus and releases it on Escape, overview, hiding and destroy.
  Never use `Main.pushModal` for desktop selection; it captures pointer input too.

### Clutter animations
- `remove_all_transitions()` before an `ease()` that may conflict with a previous one.
- Logical state changes in `onComplete`, not when `ease()` is called.
- `ease()` applies one mode to *all* properties in the call — two different curves need two calls.
- `set_pivot_point` before scaling. The popup's corner zoom relies on it: "translation = corner
  delta, scale = anchor.width / panelWidth" only maps the panel onto the icon if the scale grows from
  the same corner the translation aligned.
- **A removed transition is not a finished transition.** Its `'stopped'` arrives with
  `finished=false` and `onComplete` never runs. Anything that counts in-flight animations has to zero
  its counter by hand in `clear()` and carry an independent watchdog.
- **Every number is checked with `Number.isFinite` before it touches an actor.** `get_transformed_*`
  returns NaN over an actor without a valid allocation. A skipped flight is ugly; a NaN flight dams
  the surface forever and kills dragging for the rest of the session.

### Logging
- `log('[ArcDesk] …')` for lifecycle tracing, `console.warn('[ArcDesk] …')` for anything that must
  always appear, `logError(e, '[ArcDesk] …')` in every catch. Never `console.log` for something that
  matters — on some versions it is filtered below `notice`.

### What **not** to do
- Don't add a plain `St.Widget` to `global.window_group`, don't anchor to `backgroundActor`, don't
  write overview/lock-screen hiding by hand. All three are covered above.
- Don't construct a second `DeskLayout`, and don't connect `changed::desk-items` outside it. With one
  surface per monitor this is easier to get wrong than it used to be: the model belongs to the
  manager, not to a surface.
- Don't subscribe to `layout.onExternalChange()` from a surface, and don't connect
  `monitors-changed` outside the manager.
- Don't rewrite a placement because the monitor it names is unplugged. Display it on the primary and
  leave the record alone — same discipline as the col/row clamp.
- Don't use `Main.pushModal` for desktop selection; use normal keyboard focus.
- Don't reflow the desktop. Positions are the user's, not ours.
- Don't rebuild the grid inline from `acceptDrop`.
- Don't use `@import` in the stylesheet: `St`'s `parse_stylesheet()` sets `app_data = FALSE`, so
  imported rules land at cascade origin 0 (UA) instead of 6 (extension) and lose to a user theme's
  `!important`. Concatenation, always.
- Don't write CSS custom properties (`--x: y`), CSS nesting, or a property name with a leading
  underscore. Any one of them discards the **entire** stylesheet (errcode 15) and the Shell
  force-disables the extension.

## Testing a change

1. Edit, then log out and back in (see **How to reload**).
2. `journalctl --user -f -o cat _COMM=gnome-shell | grep -i arcdesk` — there should be no
   `[ArcDesk]` errors, and exactly one line from `doubleClick.js` saying which click path was taken.
3. Smoke test, in this order — each step is a different subsystem:
   - Icons appear on the wallpaper after login, below every window, absent in the overview.
   - Single click selects; double click opens (or single click opens, with the pref off).
   - Drag an icon to an empty slot → it moves and stays there after a logout.
   - Drag onto the centre of another app → they merge into a folder; the folder opens on click.
   - Drag onto the edge of another app → they swap.
   - Drag the last app out of a folder → the folder dissolves into that app, in the folder's slot.
   - Right-click an icon → the menu opens above it and its "Fixar na dock" label matches ArcDock.
   - Open ArcDock's prefs, unpin something, and watch the ArcDesk Items page follow.
   - Change the icon size in prefs → every surface rebuilds, positions preserved.
4. With a second monitor attached, the per-monitor subsystems — none of these can be checked on one
   screen, and every one of them has a failure mode that looks like "it works" from the primary:
   - Both screens draw a grid after login, each with its own slots.
   - Drag an icon from one screen to the other → it lands there, and it is still there after a
     logout. The origin slot is released and no highlight is left lit behind on either screen.
   - Drag an icon onto an occupied cell of the *other* screen → merge and swap both work across the
     boundary.
   - Click into one grid, then into the other, then press Escape → the session is still responsive.
     A wedge here is the two-grabs bug, and the only way out is a TTY.
   - Open a folder on the secondary screen → the popup opens on *that* screen.
   - Unplug the second monitor → its items appear on the primary; `dconf read
     /org/gnome/shell/extensions/arcdesk/desk-placements` still shows their original `mon`. Plug it
     back in → they return to where they were.
   - The Items page shows a monitor for each row, and "Primary monitor" for a record written before
     `mon` existed.

## Files

- `extension.js` — entry point. Keep it **thin**, and it is thinner than it was: key reads with
  `?? default` (with `icon-size` re-clamped against `SIZE.ICON_MIN`/`ICON_MAX`, because dconf is
  editable by hand and a tampered key must not ask for a 10x icon), one `DeskManager`, the eight
  appearance listeners, `warnIfDingActive()`, and cleanup. No surfaces, no popup, no
  `monitors-changed`.
- `prefs.js` — Adw preferences. Every write guarded by a read-compare; it is another process, so an
  unguarded write bounces back through `changed::` and can rebuild the surfaces under the user's
  hand. The Items page reads `desk-placements` to show which monitor each item is on, **display
  only**: moving an item between screens is a drag on the desktop, and a control here would have to
  know how many monitors exist — which this process cannot see, there being no `Main.layoutManager`
  outside the shell.
- `src/*.js` — modules by responsibility (see the tree above).
- `src/CONTRACT.md` — the binding interface between the modules. Read it before touching a signature,
  and read **AMENDMENT 1 — one grid per monitor** at the end of it: it supersedes every
  "primary monitor" statement in the body above it.
- `schemas/` — the gschema. `desk-items` is a public contract with ArcDock; recompile with
  `glib-compile-schemas schemas/` after any change.
- `stylesheet.css` — **generated**. Edit `~/.local/share/arcsuite/local.css` and run `sync.sh`.
